# Окно характеристик активного мода

Рецепт для Gothic II «Ночь Ворона» 2.6 fix (G2A), Windows x86 и Union. Проверенная ревизия примера — G2NRcharstats 0.1.1. [Исходники](https://github.com/piratvasyamorexod-alt/G2NRcharstats/tree/059fe19279dbde91931c95abc672aee8ef06279e) · [Оформление игровых окон](modal-ui.md#единый-стиль-игровых-окон)

## Перехват штатного окна

1. Оберни `oCStatusScreen::Show()` (G2A 2.6 fix, `0x0047ED60`) короткой сессией, привязанной к `m_pStatusMenu`. Вызови оригинал. Он вызывает `oCMenu_Status::InitForDisplay()` (`0x0047DDC0`), затем запускает меню. В «Одиссее» скриптовый хук в конце `InitForDisplay()` записывает дополнительные значения через `zCMenuItem::SetText()`.
2. При первой отрисовке активного меню, когда `m_screenInitDone` выставлен, обойди `m_listItems`. Возьми ID, координаты и `GetText(0)` у каждой подходящей строки. Храни копии текста для отрисовки. У обычных элементов проверь `owner`, `GetIsVisible()` и `m_bDontRender`. Группируй строки по позиции с допуском на небольшие смещения столбцов. Так сохраняются подписи, язык, навыки и формат значений текущих скриптов, включая пары вроде `46%/31%`.
3. В хуке `zCView::DrawItems()` (`0x007A6750`) подмени отрисовку самого `m_pWindow` этой сессии. Другие поверхности передавай оригиналу. Если список пуст или содержит неизвестный вид виджетов, оставь штатное окно. Управление паузой и основной жизненный цикл остаются у движка. [Открытие и хуки](https://github.com/piratvasyamorexod-alt/G2NRcharstats/blob/059fe19279dbde91931c95abc672aee8ef06279e/src/Plugin.ipp#L464-L529) · [Чтение элементов и группировка](https://github.com/piratvasyamorexod-alt/G2NRcharstats/blob/059fe19279dbde91931c95abc672aee8ef06279e/src/Plugin.ipp#L34-L75) · [Группировка по строкам](https://github.com/piratvasyamorexod-alt/G2NRcharstats/blob/059fe19279dbde91931c95abc672aee8ef06279e/src/status_layout.hpp#L42-L84)

## Страницы «Одиссеи» 2.7.5.2

В `MENU_STATUS` пункт `MENU_ITEM_SWITCH_HANDICRAFT_CHOICE` выбирает значение `MOD_ODYSSEE/showMoreInfo`. У строк обеих страниц то же имя настройки в полях `m_parHideIfOptionSectionSet` и `m_parHideIfOptionSet`. Значение `m_parHideOnValue` указывает страницу, на которой строку следует скрыть. Механизм выбора меняет настройку, а видимость пересчитывается при подготовке штатного меню. Старый путь с отправкой `KEY_RIGHT` и `KEY_RETURN` из клика приводил к устаревшему списку и мерцанию при закрытии. `Enter` запускает `MENU_STATUS` повторно через `SEL_ACTION_STARTMENU`.

Сними два снимка строк за одно открытие. Применяй условие страницы только к элементам, чья настройка совпадает с распознанным переключателем. Такие элементы могут лежать в `m_listItems` с заполненным текстом, даже когда их нет среди видимых дочерних элементов. Для остальных строк используй их штатную видимость. Рецепт предполагает, что мод уже заполнил тексты обеих страниц. Это проверяется в скрипте обновления меню конкретной версии мода.

```cpp
// page is 0 or 1. Use -1 when the row has no matching page setting.
bool VisibleOnPage(bool nativeVisible, int hideOnPage, int page) {
    return hideOnPage == 0 || hideOnPage == 1 ? page != hideOnPage : nativeVisible;
}
```

Клик по вкладке и стрелки меняют индекс снимка внутри окна. Обработчик перехватывает `Enter` для этого переключателя. При `Esc` прекращай брать ввод для вкладок и подавляй остаточные кадры штатной панели до выхода из `Show()`. Сохраняй это условие и после того, как движок уже сменил активное меню. Мышь освобождается при выходе из сессии или потере фокуса. [Определение страниц и чтение строк](https://github.com/piratvasyamorexod-alt/G2NRcharstats/blob/059fe19279dbde91931c95abc672aee8ef06279e/src/Plugin.ipp#L30-L75) · [Клавиши, мышь и закрытие](https://github.com/piratvasyamorexod-alt/G2NRcharstats/blob/059fe19279dbde91931c95abc672aee8ef06279e/src/Plugin.ipp#L410-L483)


## Подсказки к характеристикам

Штатное меню показывает названия и значения. Смысл подсказки зависит от правил активной игры. Используй ID ячейки из `Capture()`. В «Ночи Ворона» и «Одиссее» `MENU_ITEM_ATTRIBUTE_1` соответствует силе, `MENU_ITEM_ATTRIBUTE_2` — ловкости, `MENU_ITEM_TALENT_1` — владению одноручным оружием. Во время отрисовки связывай область видимой строки с ее ID, чтобы наведение работало после прокрутки и смены вкладки. Число для расчета считывай из текущего состояния героя, например через `oCNpc::GetAttribute()` или `GetHitChance()`. Текст на экране оставляй в формате и на языке мода.

Для модовых правил сопоставь активный набор скриптов с проверенной версией или загрузи явно выбранное описание правил. Названия строки и наличие похожей переменной сами по себе ничего не гарантируют. Для незнакомой версии используй только подтвержденные возможности и добавляй подсказку к строке, если можешь объяснить ее по доступным данным.

### Стоимость обучения

В штатной «Ночи Ворона» и в стандартном обучении «Одиссеи» 2.7.5.2 `B_GetLearnCostAttribute` читает счетчик `REAL_STRENGTH` или `REAL_DEXTERITY`. Смотри по скрипту его обновления, какие бонусы попадают в счетчик. У «Одиссеи» это `hero.aivar[81]` для силы и `hero.aivar[82]` для ловкости. `Update_Character_Menu` выводит эти значения рядом с итоговыми. При активном `ODY_CHECKSNCMODE_ENABLE` скрипт пропускает этот блок обновления меню. Для режима S&C сверяй правила отдельно. [Расчет цены в MDK «Ночи Ворона»](https://github.com/dzieje-khorinis/Gothic-2-Mod-Development-Kit/blob/master/_work/Data/Scripts/CONTENT/Story/B_Story/B_GetLearnCostAttribute.d) · [Обновление счетчиков в MDK](https://github.com/dzieje-khorinis/Gothic-2-Mod-Development-Kit/blob/master/_work/Data/Scripts/CONTENT/Story/B_Story/B_RaiseAttribute.d)

| Счетчик перед уроком | Очков обучения за единицу |
| --- | ---: |
| До 29 включительно | 1 |
| 30–59 | 2 |
| 60–89 | 3 |
| 90–119 | 4 |
| От 120 | 5 |

`B_TeachAttributePoints` умножает цену на размер урока один раз перед прибавкой. Если учитель предлагает +5 и его предел позволяет, при счетчике 29 урок до 34 стоит 5 очков, а при 59 урок до 64 — 10. Следующий урок использует новый тариф. Для точной цены до цели учитывай доступные размеры уроков и предел учителя. Если они неизвестны, укажи допущение «при обучении по +1». [Покупка урока в MDK «Ночи Ворона»](https://github.com/dzieje-khorinis/Gothic-2-Mod-Development-Kit/blob/master/_work/Data/Scripts/CONTENT/Story/B_Story/B_TeachAttributePoints.d)

Пример для «Одиссеи» со скриншота. При итоговой силе 76 и счетчике 40 подсказка показывает 2 очка за +1 и 20 единиц до повышения цены. При итоговой ловкости 61 и счетчике 37 до подорожания 23 единицы. Для одноручного с итоговыми 46% и счетчиком 31% цена идет по `hero.aivar[84]`, а «Мастер» открывается при 60% итогового навыка. При сохранении бонусов и наличии подходящего учителя это еще 14 п. п. за 28 очков. Проверяй `B_GetLearnCostTalent`, `B_TeachFightTalentPercent` и переходы анимаций в `B_AddFightSkill`.

### Требования, урон и взлом

- `oCNpc::CanUse()` сравнивает требования `oCItem::cond_atr` и `cond_value` с атрибутами героя. Шпага с требованием к ловкости в штатной «Ночи Ворона» использует силу в формуле урона ближнего боя. В «Одиссее» 2.7.5.2 `INITDAMAGE` подключает `DMG_ONDMG` к обработке попадания. В проверенной ветке для клинков с `cond_atr[2] == ATR_DEXTERITY` скрипт использует ловкость, а в ветке обычных арбалетов — силу. Для мушкетной пули есть отдельная ветка с ловкостью. Вывод о масштабировании урона проверяй по обработчику попадания.
- В штатном G2A 2.6 fix ошибка при взломе может сломать отмычку. Движок бросает число от 1 до 100 и сравнивает его с текущей ловкостью. При 61 ловкости номинальный риск 39%, при 100 риск исчезает. В «Одиссее» поверх этого есть пороги доступа к замкам. Семейства `B_SCHLOESSERKNACKENSTUFE*` и `B_TUERSCHLOSSKNACKENSTUFE*` проверяют талант и ловкость 60, 130, 200, 250 для ступеней II–V. Скрипты отдельных замков учитывают ключи и специальные отмычки. При изученном III и ловкости 61 можно показать сразу две разные строки, «Риск поломки при ошибке 39%» и «Замки III уровня · не хватает 69 ловкости».

Правила проверены статически по `Gothic2.exe`, скриптам MDK и двум вариантам `GOTHIC.DAT` «Одиссеи» 2.7.5.2. Подсказки описаны как расширение рецепта. Для игровой проверки сравни цены уроков +1 и +5 при счетчиках 29/30 и 59/60, затем проверь строку рядом с порогом замка и с экипировкой, меняющей итоговый атрибут. При смене сборки повтори проверку по активным скриптам.
