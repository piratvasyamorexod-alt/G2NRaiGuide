# Мышь в игре на паузе

Проверенный пример — Odyssee Quest Inspector 1.0.7 под Gothic II «Ночь Ворона» 2.6 fix, Union и русскую «Одиссею» 2.7.5.2. Во время отладки пользовательская сборка показывала GD3D11 `git-4ef627987`. После установки 1.0.7 пользователь подтвердил, что управление работает и курсор движется плавно. Частота кадров и задержка в самой игре отдельно не измерялись. [Исходники 1.0.7](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/tree/c6cacbd167837afe84364069ecc25a29e97bca81) · [Windows-сборка и тесты](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/actions/runs/45235472806)

## Экранные координаты ZenGin

1. Получи границы клиентской области через `GetClientRect` и переведи обе точки в координаты рабочего стола через `ClientToScreen`. Прочитай положение с `GetCursorPos`. Координата из события служит запасным источником при сбое опроса. Проверяй, что точка попадает в клиентскую область.
2. Бери размеры корневого `screen` из `psizex` и `psizey`. В G2A 2.6 fix `zCView::GetPixelSize` по адресу `0x007A7830` пишет выходные параметры только при наличии `owner`. У корневого окна его нет. `zCView::SetMode` по адресу `0x007ABDB0` записывает пиксельные размеры корня напрямую.
3. Масштабируй клиентскую точку в пиксели `screen`. Для попадания в элемент окна вычти пиксельное положение панели через `panel.GetPixelPos(x, y)`, затем преобразуй разность через `panel.anx()` и `panel.any()`. Используй единую систему координат для курсора, кнопок и прокрутки. [Преобразование и прием ввода](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/Plugin.ipp#L466-L578) · [Границы окна в Win32](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/journal_mouse_win32.hpp#L23-L31)

Минимальный фрагмент для `Gothic_II_Addon`. `client` и `desktop` здесь заданы в координатах рабочего стола, `screen` доступен.

```cpp
std::optional<POINT> CursorPixels(const RECT& client, POINT desktop) {
    const int width = screen->psizex;
    const int height = screen->psizey;
    if (width <= 0 || height <= 0 || !PtInRect(&client, desktop)) return std::nullopt;
    return POINT{
        (std::min)(width - 1, MulDiv(desktop.x - client.left, width, client.right - client.left)),
        (std::min)(height - 1, MulDiv(desktop.y - client.top, height, client.bottom - client.top))
    };
}
```

## Как принимать ввод

Если штатный ввод уже работает в новом плагине, проверь `zinput->GetMousePos()`, `GetMouseButtonPressedLeft()` и события `MOUSE_WHEELUP` и `MOUSE_WHEELDOWN`. `GetMousePos()` в G2A дает относительное движение, которое надо накапливать для виртуального курсора. В журнале подтвержден путь с абсолютной позицией Windows.

Сохраняй исходное состояние `zINPUT_MOUSE`. В G2A `zinput->SetDeviceEnabled(zINPUT_MOUSE, FALSE)` меняет флаг опроса. Для немедленного применения к DirectInput у 2.6 fix есть `int __cdecl SetAcquireMouse()` по адресу `0x004D3D30`. В проверенном примере флаг и захват переключаются после установки обработчика мыши, а при выходе восстанавливаются. Для другой версии движка перепроверь адрес и сигнатуру. [Захват и возврат мыши](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/Plugin.ipp#L441-L453) · [Захват мыши в GD3D11](https://github.com/kirides/GD3D11/blob/4ef62798780f80116fd3f6d885183340014fb51e/D3D11Engine/GothicAPI.cpp#L858-L915)

В проверенной сборке журнал использует `WH_MOUSE_LL` и сообщения самого окна игры. Установи низкоуровневый хук в отдельном потоке с очередью сообщений. Обработчик принимает ввод только пока корневое окно игры в фокусе, сохраняет состояние под короткой блокировкой и передает управление через `CallNextHookEx`. Основной поток забирает накопленное состояние во время опроса. При закрытии сними наблюдение за окном, заверши очередь потока и дождись его завершения до освобождения состояния. [Реализация MouseEvents](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/journal_mouse_win32.hpp#L33-L203) · [LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)

- Сохраняй факт нажатия отдельно от удержания. Короткий клик между двумя кадрами должен сработать один раз, а удержание должно вести бегунок до отпускания.
- Накапливай дельту колесика до `WHEEL_DELTA` и переноси остаток на следующий опрос. Для сообщений окна считывай знаковую дельту через `GET_WHEEL_DELTA_WPARAM`. Выбирай один источник для каждого типа события, чтобы одно нажатие или прокрутка не обрабатывались дважды.
- `WH_CALLWNDPROC` на оконном потоке дает запасной путь для кнопки и колесика. Используй его для данного типа события, пока `WH_MOUSE_LL` еще не выдал событие этого типа. Штатные события ZenGin остаются доступными как запасной путь.
- Запоминай потерю фокуса через `WM_ACTIVATEAPP` и `WM_ACTIVATE`. Между уходом из игры и возвратом отрисовка может не вызвать ни одного кадра. Сбрасывай очередь, удержание и перетаскивание. Повторно открывай сеанс курсора при возвращении фокуса. [События, накопление и фокус](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/journal_mouse_win32.hpp#L49-L110) · [Потребление событий в журнале](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/Plugin.ipp#L522-L575)

В G2NRinventory 0.1.28 хук установлен в игровом потоке, который уже обрабатывает сообщения Windows. Для перетаскивания запоминается максимальное смещение во время удержания, а действие определяется по точке отпускания. Этот путь проверен пользователем для переноса предметов в хотбар. [Клик и перетаскивание](inventory.md#клик-и-перетаскивание)

## Плавность и видимость курсора

В проверенной ревизии GD3D11 параметр `PausedFpsLimit` ограничивает частоту кадров меню на паузе. Нарисованный движком курсор обновляется с этой частотой. `WH_MOUSE_LL` вызывается в потоке, установившем хук. Выделение потока для ввода позволяет обработать движение, даже когда игровой поток ждет следующего кадра. [Ограничитель GD3D11](https://github.com/kirides/GD3D11/blob/4ef62798780f80116fd3f6d885183340014fb51e/D3D11Engine/BaseGraphicsEngine.cpp#L26-L42) · [Модель потока Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc#remarks)

Во время работы журнала держи системную стрелку видимой. На потоке окна поставь временный `SetWindowSubclass`. Обработай `WM_SETCURSOR` только для `HTCLIENT` в окне с фокусом. Установи стрелку через `SetCursor` и верни `TRUE`. В Gothic II исходный обработчик может скрывать ее через `ShowCursor(FALSE)`. Остальные сообщения передавай через `DefSubclassProc`. При закрытии или потере фокуса сними обработчик, сбалансируй собственные вызовы `ShowCursor(TRUE)` и восстанови прежнюю область `ClipCursor`, если она все еще принадлежит журналу. [Сеанс системного курсора](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/journal_mouse_win32.hpp#L205-L269) · [WM_SETCURSOR](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-setcursor)

Когда `GetCursorInfo` показывает видимую системную стрелку с действительным дескриптором, рисует Windows. Если системный курсор скрыт, прочитай свежую точку через `GetCursorPos` непосредственно перед выводом резервной текстуры в `Blit()`. Это убирает дополнительную задержку между опросом журнала и отрисовкой. При разборе комплекта инвентаря Хедина обнаружено, что `zCViewCursor::FrameBegin` также получает позицию через `GetCursorPos`, а состояние кнопки читает из ZenGin. При переносе такого подхода сопоставляй весь путь до окна, включая фокус, захват мыши и преобразование координат. [Резервный курсор в кадре](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/src/Plugin.ipp#L613-L637)

## Диагностика от установки до игры

Сначала проверь номер сборки в углу окна. В журнале `Shift+D` показывает `X` и `Y` в пикселях `screen`, `P` — накопленное количество событий, `C` — обработанные нажатия, `W` — шаги колесика. Нарастание `P` при движении ожидаемо. Клики и прокрутку проверяй отдельно по `C` и `W`. Неправдоподобные `X` и `Y` указывают, что нужно проверить размеры и перенос между координатами рабочего стола, окна и движка.

| Версия | Что показал запуск в игре | Что вынести для следующей задачи |
| --- | --- | --- |
| 1.0.1 | Счетчики кадров `F` и опросов `I` росли, `C0 W0` сохранялись | Отдельно проверяй цикл обновления и доставку конкретных событий |
| 1.0.2 | Системная стрелка двигалась, клики и колесико не работали, после Alt+Tab стрелка пропадала | Видимость указателя проверяется отдельно от маршрута ввода и возврата фокуса |
| 1.0.3 | В углу появился след из полосок | Сверяй формат в заголовке `ZTEX` и фактическое сжатие. DXT3 имеет номер `0x0C`, DXT1 — `0x0A` |
| 1.0.4 | Raw Input зарегистрировался. Счетчик оставался на нуле или останавливался после одного-двух пакетов. Апостроф требовал второго нажатия | Регистрация и возврат окна-получателя проверяют лишь настройку. Windows держит одну регистрацию на класс Raw Input внутри процесса. Проверяй реальные события в целевой сборке |
| 1.0.5 | Апостроф заработал с первого раза. Движение давало события, но снимок показал `X10157284` на экране 1920×1080 | Если события есть, проверь преобразование координат. Размеры корневого окна через `GetPixelSize` оказались неинициализированными |
| 1.0.6 | Пользователь подтвердил, что управление заработало. Движение курсора оставалось резким | Исправная навигация и плавность проверяются раздельно |
| 1.0.7 | Пользователь подтвердил плавное движение и рабочее управление | Выноси низкоуровневый опрос из потока с ограничением кадров. Проверяй видимость системной стрелки и возврат фокуса |

## Как повторить проверку

1. На локальном стенде исходи из того, что `GetPixelSize` корня оставляет выходные аргументы неизменными. Проверь попадание в строку при клиентской области с ненулевым началом и отличающемся размере окна. Проверь, что при обычном системном курсоре журнал не рисует второй и что запасная текстура берет актуальную позицию в кадре.
2. В Windows-тесте с `SendInput` проверь движение без обработки сообщений основным потоком, быстрый клик, удержание, несколько долей одного шага колесика, смену фокуса и восстановление обработчика окна. Отдельно проверь прямые сообщения кнопки и колесика. Этот тест использует тестовое окно Windows. [Тест 1.0.7](https://github.com/piratvasyamorexod-alt/OdysseeQuestInspector/blob/c6cacbd167837afe84364069ecc25a29e97bca81/tests/win32/journal_mouse.cpp)
3. В игре проверь открытие одним нажатием, смену вкладок, выбор строки, прокрутку обеих колонок, перетаскивание бегунка и возврат после Alt+Tab. Закрой журнал мышью и клавиатурой. Проверь, что до закрытия мир стоит на паузе, а после закрытия возвращается игровое управление. В отчете укажи, что видел сам или подтвердил пользователь, и привяжи результат к версии VDF.
