# Работа с базой знаний Gothic и Union

Используй материалы для задачи пользователя. Сначала уточни целевую игру, способ интеграции и версию инструментов из проекта. Если задача уже определяет эти параметры, переходи сразу к нужному разделу.

| Задача | Раздел |
| --- | --- |
| Собрать Union-плагин для Gothic II «Ночь Ворона» и получить VDF | [Сборка под Windows](docs/union/windows-build.md) |
| Открыть окно на паузе, настроить клавиши, панели и прокрутку | [Игровой интерфейс и ввод](docs/union/modal-ui.md) |
| Перерисовать штатные характеристики, сохранив данные и страницы активного мода | [Окно характеристик](docs/union/character-status.md) |
| Исправить координаты, клики, рывки курсора и возврат после Alt+Tab | [Мышь на паузе](docs/union/mouse-input.md) |
| Сделать инвентарь, торговлю и хотбар с перетаскиванием и сохранением | [Инвентарь, торговля и хотбар](docs/union/inventory.md) |
| Прочитать квесты, флаги и этапы из игры и сохранения | [Состояние квестов](docs/union/quest-state.md) |
| Сделать анимацию персонажа в Blender и подключить ее в игре | [Анимации](docs/animation/README.md) |

Открывай только относящиеся к задаче разделы и связанные с ними исходники. В новом проекте проверяй сигнатуры и поведение в его версии SDK. Переноси алгоритм и проверенные вызовы, адаптируя их к архитектуре проекта.

Проверку сборкой, автоматический тест и запуск в игре отмечай отдельно. Если в рецепте есть частичная проверка или открытый вопрос, учитывай это при выборе подхода и при отчете о результате.

Когда пользователь поручает пополнить базу, запиши переносимый прием. Укажи задачу, целевую версию, минимальный пример, ссылку на ревизию проекта и шаги проверки. Если есть результат запуска в игре, запиши версию игры, рендерер и наблюдаемое поведение. При появлении нового раздела добавь ссылку в таблицу выше.
